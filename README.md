# LM960B 双模自组网 Demo

**用途**：香港消防署演示 — 展示 PLBUS 双模（HPLC有线 + Sub-1GHz无线）自组网能力
**硬件**：力合微 LM960B-IC100（主模组）× 1 + LM960B-IC300（从模组）× 2-3
**依赖**：无需 PostgreSQL/Redis/EMQX，插上模组即可运行

---

## 演示场景

1. 启动 demo，屏幕显示 1主 + N从节点在线，模式 = 双模
2. 周期查询，节点状态稳定
3. **人为制造链路中断**（断开某个从节点的有线路径，或给节点掉电）
4. 页面出现 timeout + 模式/可达性变化事件
5. 数秒后节点恢复可达（走备用无线链路）
6. 说明：双模网络具备自愈能力，节点不中断可管理性

## 串口协议：两层结构

> 详细协议提取文档：`docs/plbus_protocol_reference.md`
> （已整理自 `hplc_docs/PLBUS高速双模通信模块软件开发指南_V1.0.pdf`，后续开发优先查该文档）

LM960B 模组使用 **Uapps 二进制协议**，不是 AT 文本命令。协议分两层：

```
┌─────────────────────────────────────┐
│  应用层：Uapps（基于 CoAP）           │  ← 服务项查询/响应/主动上报
├─────────────────────────────────────┤
│  数据链路层：串口帧（含前导码+CRC）    │  ← 串口收发的实际字节
└─────────────────────────────────────┘
```

上位机收到串口字节后，先按数据链路层解帧（去前导码、校验CRC），再解析内层 Uapps 报文。

### 数据链路层：串口帧

前导码固定为：
```
1B 1B 1B 1B 1B 0A 1B 0A

### Uapps 报文格式（来自软件开发指南 §5.4.1）

Uapps 基于 IETF CoAP 协议，报文通过数据链路层传输。

**报文整体结构**：
```
[ 消息头 ] [ CoAP选项（变长）] [ 0xFF 标志1 ] [ 数据内容头/Uapps选项（变长）] [ 0xFF 标志2 ] [ 内容数据（变长）]
```

**消息头字段**（第一个字节按位划分）：

| 字段 | 比特宽度 | 说明 |
|------|----------|------|
| VER | 2 | 版本，固定为 0 |
| T（消息类型） | 2 | `00`=CON（要求确认）/ `01`=NON（不要求确认）/ `10`=ACK（确认，针对CON）/ `11`=保留 |
| TKL | 4 | Token 长度，0-8，0=无 token |
| 请求方法/响应码 | 8 | 高3位为类(c)，低5位为细节(dd)，表达为 `c.dd`。请求时 c=0，dd 为 GET/PUT/POST/DELETE 等；响应时 T=ACK，c.dd 给出结果码 |
| ID | 16 | 消息ID，network-byte-order（大端）。每次新消息+1，ACK 的 ID 与对应请求相同 |
| TOKEN | 变长 | 字节数由 TKL 决定，大端序 |

**选项与标志**：
- **CoAP 选项**：0个或多个，选项后第1字节为 `0xFF` 则选项域结束
- **标志1**：`0xFF`，标识 CoAP 选项域结束，后随 Uapps 选项及数据内容
- **数据内容头（Uapps 选项）**：0个或多个 Uapps 选项，格式同 CoAP 选项格式；选项后第1字节为 `0xFF` 则结束
- **标志2**：`0xFF`，标识 Uapps 选项域结束；若有 SIZE 选项则数据长度由 SIZE 确定，否则由数据块结束确定
- **内容数据**：长度由 Uapps 选项 SIZE 给出；格式由选项 FORMAT 给出；若无 FORMAT 则默认字节流

**通信模式**：请求-响应模式，任何一端都可发起请求。

### Demo 需要实现的服务项（最小集）

| 服务项 | 功能 | 用途 |
|--------|------|------|
| `@0/2` | 查询 MAC 地址 | 识别节点身份 |
| `@0/3/20` | 查询信道模式 | 0=PLC有线, 1=无线, 2=双模 |
| `@0/3/21` | 查询无线频段 | 辅助信息 |
| `@1.noda/104/1` | 单播 ping | 判断链路可达性，测量 RTT |

**节点上线主动上报**（模组自动推送，无需轮询）：
- 从节点加入网络时，主模组会主动上报 NODE_JOIN 事件
- 包含从节点 MAC、信号强度、接入模式（有线/无线）

**双模切换**：
- 模组**自动**处理有线/无线切换，上位机无需干预
- 切换后模组会主动上报模式变化事件
- 上位机只需监听上报帧即可感知切换

│  /│\             │  SUB1 | ✓在线 | 双模 | 12ms  │

│                  │  SUB3 | ✓在线 | 无线 | 45ms  │

│  灰线=不可达      │                              │
└──────────────────┴──────────────────────────────┘
```

节点颜色：
- 绿色 = 在线（PLC有线）
- 蓝色 = 在线（无线）
- 橙色 = 在线（双模）
- 灰色 = 离线/超时

## 开发规范

1. **禁止轻易执行"恢复出厂设置"类硬件操作**：涉及模组出厂复位、清除配置等不可逆操作的代码，必须有明确的二次确认机制，且不得在自动化流程（轮询、重试、初始化）中自动触发。
2. **写入失败时分次写入**：向模组写入数据失败后，不得整包重试，应将数据拆分为更小的分片逐次写入，每次写入后等待确认再继续，避免因帧过长或缓冲区满导致连续失败。
3. **版本号规范**：遵循 [Semantic Versioning](https://semver.org/lang/zh-CN/)，格式为 `MAJOR.MINOR.PATCH`：
   - `MAJOR`：不兼容的协议或接口变更
   - `MINOR`：向后兼容的新功能（新 demo 场景、新联调功能）
   - `PATCH`：向后兼容的 bug 修复
   - 开发阶段使用 `0.x.y`，当前版本在 `MILESTONE.md` 中维护
   - 每次发布打 git tag，格式：`v0.1.0`
